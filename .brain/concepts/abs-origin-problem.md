# abs 要解决的问题

一句话：**AI 编程里的工作内容和经验都是琐碎的**，跨工具、跨会话、跨天之后就散了。

## 触发场景

判断某个功能该不该加进 abs 时，回到这一条对照——它服务不服务于「让琐碎经验不流失」。

## 原始表述（2026-09-07，第一场会话）

> 我是一个程序员，在 ai coding 过程中使用 ai 智能体编程有个很大的问题：
> 所有的工作内容和经验都是琐碎的、比较乱。比如用 Claude、opencode 各种 AI 编辑器，
> 跨各种会话，经验、进度、日程都是琐碎的。
> 我想写一个 skill，能在每轮会话开始对保存经验和 todo 进行指导，结束进行总结并保存到项目根目录。

三个原始诉求，对应到现在的机制：

| 原始诉求 | 现在的实现 |
|---|---|
| 会话开始给指导 | `abs load`（Rules + 滞留 + 看板 + 最近动作） |
| 过程中保存经验和 todo | `abs todo` / `abs capture` / `abs note` |
| 结束做总结存到项目根 | 收尾循环 + `abs log` + `abs summon` 托底 |

## 🛠 判据：加功能前问一句

**这个功能服务的是「让琐碎经验不流失」，还是「让工具更完整」？**

- 前者 → 值得做
- 后者 → 大概率是自嗨，删掉（见 [[feature-delete-not-patch]]）

反面例子（真实发生过）：`abs serve` 端口服务、`## Roadmap` 区、
todo 自动登记 —— 都是「让工具更完整」，最后全被删。

## 验证

看 `abs load` 的首屏：如果它不能让人一眼说出「上会话做到哪、现在该干什么」，
说明机制偏离了原始诉求，该收窄而不是加东西。
