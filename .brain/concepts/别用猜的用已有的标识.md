# 能拿到确切标识就别猜：按 mtime 猜会选错

用「最近修改的文件」代表「我刚在操作的那个」是个近似。**单进程单人时它几乎总对，所以这个错能潜伏很久**——直到有第二个东西同时存在。

## 触发场景

- 从一批同类文件里挑「当前那个」，用的是时间、排序、大小这类间接特征
- 而系统其实**已经知道确切是哪个**（有 id、有句柄、有上下文变量）
- 平时只有一份，测不出来

## ❌ 表现（实测 2026-11-05）

hook 在会话关闭时落会话页，调的是：

```bash
abs ingest --last --auto     # --last = 按 mtime 取最新的会话文件
```

同时开着两个 pi 会话时：

```
会话 A（要关闭的）  mtime 10:00
会话 B（还在写的）  mtime 12:00

关 A → hook 触发 → --last 选中 B → 落了 B 的页
```

**这场关掉的会话一条记录都没有，而另一场还在进行的被提前落成页。**
从结果上看不出错——页照样生成、格式照样正确，只是内容属于别人。

更要紧的是：`hooks/abs.pi.ts` 里**早就有 `sessionIdFor(ctx)`**，它就是用来取本会话 id 的，
只是这个函数被用在了别处（登记 todo 的 sid），落会话页这里没想到用它。

## 🛠 做法

```js
// 改前：靠猜
spawn(node, [ABS_BIN, "ingest", "--last", "--auto"])

// 改后：有确切 id 就用它，拿不到才退回猜
const args = ["ingest", "--auto"];
if (sid) args.push("--session", sid);
else args.push("--last");
```

`ingest` 那侧同样优先用 `--session`：

```js
if (session) {
  hit = names.find(n => n === want) || names.find(n => want.length >= 8 && n.includes(want));
  if (!hit) return `✗ 找不到 session=${want}`;   // 找不到就明说，绝不退回 --last
} else if (last) { ... }
```

**「找不到就明说、不退回猜」是关键**：一旦允许退回，错就变成静默的。

## 判据

写「挑当前那个」的代码前，先问：**系统里是不是已经有它的身份？**

- 有 id / 句柄 / 上下文变量 → 用它
- 只能靠时间、顺序、大小推 → 那是猜，要么明说不确定，要么在出错时明确报错

另一个判据：**近似判据只在一个元素的集合里才等于精确判据。** 一个文件的「最新」就是它自己，
两个文件时「最新」开始有歧义。所以这类 bug 的测试必须造两个。

## 验证

```bash
node --test test/ingest.test.js          # --session 指定会话 / 截断 id / 找不到时明说
node --test test/plugin-behavior.test.js # 关会话时传的是 sid，不是 --last
```

破坏验证（2026-11-05 实测）：把 hook 改回不传 sid → 立刻变红（`pass 76 fail 1`），还原后转绿。
