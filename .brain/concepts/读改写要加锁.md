# 读-改-写不加锁：并发时后写的盖掉先写的

`读文件 → 改内存 → 写回` 这三步之间有窗口。窗口里进来的另一个进程，它的修改会被后写的一方整体覆盖。

**它不报错。** 症状出现在很久以后：某个本该记住的东西，下次又「忘了」。

## 触发场景

- 用 JSON / 单文件当一个小的共享状态（账本、缓存、索引）
- 写入是「读出全部 → 改一处 → 写回全部」
- 有多个入口几乎同时触发（多个会话同时关闭、多个 hook 同时跑）

## ❌ 表现（实测 2026-11-05）

`~/.abs/summarized.json` 记「哪些会话已经落过页」。原来的写法：

```js
const book = await readLedger(path);   // 读出全部
book.files[name] = {...};              // 改一条
await writeLedger(book, path);         // 写回全部
```

两个会话同时关闭 → 两个 `ingest` 进程：

```
进程 A 读 → {1 条}
进程 B 读 → {1 条}        ← 同时读到同一份旧账本
进程 A 写 → {2 条}（含自己的）
进程 B 写 → {2 条}（含自己的，不含 A 的）  ← A 那条消失
```

**实测并发 30 次：只剩 1 条，丢了 29 条。**

还有个更小的坑叠在上面：tmp 名原来是 `` `${path}.tmp-${Date.now()}` ``。
同一毫秒内起的两个进程生成**完全相同**的 tmp 名——前一个 `rename` 把文件改走后，
后一个对着不存在的名字操作，抛 `ENOENT`：

```
Error: ENOENT: rename '/private/tmp/race/race-ledger.json.tmp-1793863871837'
     -> '/private/tmp/race/race-ledger.json'
```

## 🛠 做法

**一，tmp 名必须带随机段。** 仓库其它落盘点早就在用 `${Date.now()}-${random}`，账本这里漏了：

```js
const tmp = `${path}.tmp-${Date.now()}-${Math.random().toString(36).slice(2, 8)}`;
```

**二，读-改-写整段加锁。** 仓库已有 `lock.js` 的 `editFile`（按文件建 `.lock`，拿不到就排队重试，
带过期残留回收）。包一层就行：

```js
export async function updateLedger(mutator, path = ledgerPath()) {
  await editFile(path, async (current) => {
    const book = parseOrEmpty(current);   // 锁内读，才是权威最新内容
    await mutator(book);                  // 就地改
    return { text: JSON.stringify(book, null, 2) + '\n' };
  });
}
```

**关键：读必须发生在锁内。** 先在锁外读、再进锁改，等于没加锁。

## 判据

写「读一个整体 → 改一块 → 写回整体」之前，先问：
**同一时刻可能有第二个进程做同样的事吗？**

会 → 必须加锁，且读要在锁内。
不会（单进程、单用户、串行调用）→ 先不加，但把这条判断写在注释里，
因为「现在不会」很容易变成「以后会」。

## 验证

```bash
node --test test/summon.test.js   # 并发 30 次一条不丢 + tmp 不残留
```

破坏性验证（2026-11-05 实测）：把 `updateLedger` 改回无锁读-改-写 →
该测试立刻变红（`pass 12 fail 1`），还原后转绿。

端到端：10 个 detached 进程同时落页 → 页 10 / index 10 / 账本 10，`summon` 报 0 未落页。
