# 概念：机制的「跑了」不等于「起作用了」

## 触发场景
刚装好/改好一个机制（注入、守卫、hook、提醒、门禁），**日志显示它跑了**，
于是准备宣布"已生效"。这时先停一下。

也适用于：别人问"这个机制现在有效吗"，而你手上的证据只有一句
`xxx=on` 或"没报错"。

一句话判据：**我的日志证明的是"代码被执行了"，还是"目标对象真的被改变了"？**
这两件事之间通常隔着一层分支。

## ❌ 表现
机制日志报 `on`，而它**实际什么也没做** —— 且没有任何报错。

2026-10-06 本仓实测：

```
injectTodoGuidelines() 返回值的含义 = 「六条常驻指引装进去了」
                                    ≠ 「看板段注入成功」

因果链：看板空 → board = null → 看板段不 push
        → LLM 没有任何具体事实可对照（机制实际没干活）
而日志：todo_guide=on（看着一切正常）
```

**为何这段特别要紧**：出问题的那一刻恰好是**最该起作用**的时刻 ——
看板为空 = 新任务刚开始 = 最该对齐的时候，而它是唯一静默的时刻。

### 这个形态很常见（不只此例）

| 日志说的 | 实际可能没发生 |
|---|---|
| `xxx=on` | 内容因分支/空值没送出去 |
| "函数被调用了" | 参数为空/条件不满足，提前 return |
| "配置已加载" | 加载了但没生效（被默认值/后写覆盖）|
| "同步完成" | 同步了 0 条（空集合也算成功）|

**共同点：日志记录的是"入口执行"，不是"结果落地"。**

## 🛠 解法

**把可观测点下沉到"结果"那一层。**

1. **不要用布尔返回值当证据**：`injectTodoGuidelines()` 返回 `true`
   只表示"六条静态指引装进去了"。要证明"看板段也进去了"，就得**看落下来的内容**：
   ```bash
   # 不是看 on/off，而是 grep 实际注入物
   grep -c "\[看板\] " <注入内容>     # 0 = 看板段没送出去
   ```
2. **日志里打"数量/内容"而非"状态"**：`todo_guide=on` → 改成
   `board_rows=3` 或 `board=none(reason=empty)`。**让静默的那个分支也留痕。**
3. **给"什么都没做"的分支单独写一条日志** —— 静默的失败最贵，
   因为它和成功在日志上长得一样。

### 配套：疗效不得在自己开的验证会话里自测

机制"跑了"之后再往下走一步 —— **它有疗效吗**？这里有个自测陷阱（2026-10-03 定的协议）：

1. **必须在【开新会话干真任务】时观察**，不能在验证会话里自测。
2. **用户别提 todo，agent 不知道自己被测**。

> 前两条同根：**注意力全在被测对象上会失真（霍桑效应）**——
> 被盯着看时的行为，和真实场景不是一回事。

3. **判据**：干完一整个真任务后看有没有对应记录。有 = 有效。
4. **记录为空 ≠ 去调那个机制的参数**，而是表明**这类机制治不了**，
   该换机制种类（见 [[remind-vs-gate]]：「靠提醒」换成「不做就过不去」）。

**为何要单列这条协议**：不先约定，"验证"会退化成"我觉得它在工作"。
而"我觉得"和"日志说 on"一样，都不是证据。

## 验证
```bash
# 1. 找"静默分支"：机制里有没有「什么都不做就 return」的路径？
grep -n "return null\|return ''" <机制实现>     # 每条都要能解释它何时触发

# 2. 该分支触发时，日志留痕了吗？（没有 → 就是下一个假信号）
#    本仓反例：injectTodoGuidelines 返回 true 但 board 为空时不 push
#    本仓正解：日志改成带 reason 的形态，如 todo_guide=off reason=no_brain

# 3. 逻辑层验证（把空/空集合/条件不满足各跑一遍）
#    本仓：test/plugin-behavior.test.js 里有「看板为空」的成对用例
```

本仓实测：看板为空时 `todo_guide=on` 而看板段未注入；
改法是**让空看板也输出事实**（而不是静默），并保留成对测试。
