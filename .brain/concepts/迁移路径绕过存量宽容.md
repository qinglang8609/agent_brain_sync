# 迁移会改行签名，存量宽容就失效了

「历史脏数据放行、只拦新引入的违规」这条设计，在有**迁移**的系统里会静默失效——
因为放行判据比的是「行的签名」，而迁移正好改签名。

## 触发场景

- 写入闸门带「存量宽容」：`prevSig` 收集写盘前的所有行，新内容里签名相同的行放行
- 同时又有格式迁移：`↳` 改成标准缩进、标签改名、字段归一
- 迁移在**校验之前**跑（通常必须如此，否则迁移前的旧行会被判成非法）

## ❌ 表现（实测 2026-11-05，zj_shop）

`abs load` 直接抛错，`abs todo` / 看板全部失效，且**不会自愈**（每次读都重走同一条路）：

```
✗ 子项里像是塞了报告/清单（第 10 行）—— 子项是一句话（最多两句），不是文档。
  原文开头: ①补 8 个会员等级 auth_rule 节点(含 pid 回填自愈) ②插 2 条会员等级种子 ③清理旧口径…
```

那条子项是 9 月留下的，内容确实违规（200+ 字、含 ①②③ 清单）。但它**早就存在**，本该被放行。

根因链条：

```
readTodo(todo.md)
  → normalizeTodo 把 "  ↳ 内容: ①补 8 个…" 迁成 "  - [ ] ①补 8 个…"
  → 惰性迁移触发 editFile 写盘
  → 闸门：text 已迁移（新签名）、prevSig 取 prev 原签名（旧签名）
  → 两边对不上 → 判成「本次新引入」→ 拒写
  → readTodo 抛错 → 所有读路径一起死
```

我把 `prev` 直接换成迁移后的版本测过，能通过——**证明差别就在这一次迁移上**。

## 🛠 修法

`prev` 也走**同一次迁移**，再取签名：

```js
let prevForSig = prev;
if (prev != null && isTodoSpec) {
  const lp = String(prev).split('\n');
  // 与上面 text 用的是同一个 migrateLegacyChild
  for (let i = 0; i < lp.length; i++) {
    const conv = migrateLegacyChild(lp[i]);
    if (conv !== null && conv !== lp[i]) lp[i] = conv;
  }
  prevForSig = lp.join('\n');
}
const prevSig = violationSignatures(prevForSig);
```

**判据：只要 text 被迁移过，prev 就必须走同一个迁移函数。** 两边的签名体系必须同源。

## 更一般的原则

**「放行判据」和「写入内容」必须经过同一套变换。** 凡是出现「先变形再校验」的地方都要问：

- 我拿来比对的基线，是不是也变形了？
- 变形函数只有一份吗？（两份就会漂移）

这类 bug 的特点：**只在有历史脏数据 + 有迁移 + 有闸门三者同时存在时触发**，
而平时测试用的都是干净数据，所以长期潜伏，一遇到真实老库就炸。

## 验证

```bash
node --test test/store.test.js   # 两条回归：readTodo 不崩 + 破坏验证
```

破坏验证（撤掉 prev 的迁移 → 两条立刻变红，2026-11-05 实测）：

```
✖ readTodo: 历史 ↳ 报告体子项只是被迁移，不让整个读失败
✖ ★ 破坏验证：把 prev 的迁移去掉，enforceBrainFormat 立刻拒写
ℹ pass 281  fail 2     ← 撤掉修复后
ℹ pass 283  fail 0     ← 还原后
```
