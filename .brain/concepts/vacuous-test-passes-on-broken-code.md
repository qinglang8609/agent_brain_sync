# 空测试：恒真断言，破坏代码也全绿

## 触发场景
给一个**刚修好的 bug** 补测试时；或写「A 与 B 必须不同 / 必须相等」这类断言时。
尤其是：新测试一跑就绿、你因此认为修复已被覆盖。

## ❌ 表现
测试通过，但把修复**回退**掉它**照样通过** —— 它测的是别的东西。

2026-09-17 实测（本仓 `test/ab.test.js`）：
修的是「A/B 两组目录随机后缀碰撞」，于是写：

```js
assert.notEqual(armDir(n,'A'), armDir(n,'B'), '两组目录不该相同');
```

绿。但把哈希回退成有 bug 的旧版（A/B 后缀确实都是 `1cy1ch`）——
**测试仍然绿**。原因：目录名里本来就有 `-A-` / `-B-` 段：

```
absab-demo2-A-1cy1ch   ← 后缀相同（bug 在）
absab-demo2-B-1cy1ch
            ↑↑
      这一段的差异让整个字符串永远不相等
```

断言恒真 ⇒ 它从没检查过后缀 ⇒ 修复是否有效，零信息。
**比没有测试更糟**：它给了"已覆盖"的假信号，让人不再看这里。

## 🛠 解法
根因：断言写在了**必然不同**的量上（整个路径），而不是**真正会出错**的量（后缀）。

修法：把断言下沉到 bug 实际所在的粒度 ——

```js
const suffixOf = p => p.split('/').pop().split('-').pop();
assert.notEqual(suffixOf(armDir(n,'A')), suffixOf(armDir(n,'B')));
```

**通用判据：问一句"我要断言的差异，是不是已经由别的字段保证了？"**
是 → 断言下沉到那个字段之外的、真正会变的粒度。

**唯一的检出手段是破坏验证**（本仓 Rule「判『等价』必须真跑到，且跑破坏验证」）：
把修复回退掉，看测试**是否变红**。恒定绿的测试 = 空测试。
注意：破坏验证必须**回退到那个 bug 的真实旧实现**，不是随便删行 ——
乱删可能让测试因别的原因变红，那是假阳性，同样证明不了断言有效。

### 为何"测试通过"给不出这个信号
绿只说明"断言成立"，不说明"断言与 bug 有关"。这两件事在代码上看不出区别，
只能靠**改变被测对象再观察测试反应**来区分 —— 这是破坏验证不可被替代的原因。

## 验证
```bash
# 1. 先确认新测试在修复版下绿
node --test test/ab.test.js        # 应 pass

# 2. 回退到 bug 的旧实现（这里：弱哈希 randSuffix + seed=expName+arm）
#    再跑同一个测试
node --test test/ab.test.js        # 必须变红，否则是空测试

# 3. 恢复修复版，确认回到绿
node --test test/ab.test.js        # 应 pass
```
实测结果：回退旧哈希后 `armDir: A/B 的随机后缀必须不同` **变红**（1 fail），
恢复后回到 24 pass —— 断言确实钉在 bug 上。

> 附带证据：本仓 `checkCriterionComparable` 那三条测试也过了同样的破坏验证
> （关掉 exit-127 检测 → 对应测试红；关掉基线全绿检测 → 对应测试红；
> 而"基线为红"那条保持绿 = 非恒真）。三条都通过才说明它们测的是各自的分支。
