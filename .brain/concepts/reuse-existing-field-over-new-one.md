# 概念：能塞进已有字段，就别新增字段

## 触发场景

要给一条已存在的数据记录**加一个属性**时（如给 todo 行加「会话 id」）。
先问一句：**能不能塞进已有字段里？** 答案常常是能，而且好处远超预期。

## ✅ 做法（2026-10-09 实测）

需求是「todo 行标出是哪个会话在做的」。两种做法：

```
新增字段: - [ ] T1 [[fanchao]] — 描述 (认领 2026-10-09) (会话 01a11eae)
塞进已有: - [ ] T1 [[fanchao]] — 描述 (认领 2026-10-09 01a11eae)
                                     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 就加在日期后面
```

**后者几乎零成本，前者要动一圈。**

## 为什么（实测出来的两条硬收益）

### 1. 「整行搬运」的地方全部自动兼容

`todo archive` 把 Done 条目搬进 `sessions/log-<日期>.md` 时是**整行搬运**的。

- 新字段 = 搬运逻辑要显式带上它 → 漏一处就丢数据
- 塞进已有字段 = **搬整行 = 自动跟着走，零改动**

实测：`(会话 …)` 加进 `(认领 日期 …)` 后，**归档代码一行没改**，
`todo.md` 里的 sid 完整出现在归档文件里。

### 2. 「通配正则」的解析点全部自动兼容

全项目 6 处解析 `(认领 …)`，其中 5 处写的是通配：

```js
.replace(/\s*\(认领[^)]*\)\s*$/, '')   // [^)]* = 除右括号外任意字符
```

`2026-10-09 01a11eae` 整体被吃掉 → **5 处零改动**。
只有 1 处写死了日期格式 `\(认领\s*\d{4}-\d{2}-\d{2}\)$` 需要改。

**若另加一个 `(会话 …)` 字段，6 处全都要改**（都要认得新字段、都要剥掉它）。

## 判据：什么时候该新增字段

| 情形 | 选择 |
|---|---|
| 新属性与旧属性**同时成立**（如「认领人」vs「完成人」） | **必须分开**（实测：A 认领 B 完成时是两个不同的值） |
| 新属性是旧属性所在的**同一个语义槽**（都是"这条任务的时间锚点"） | **塞进去** |
| 旧字段的解析全是通配 | 塞进去几乎免费 |
| 旧字段的解析写死了格式 | 塞进去要改 N 处 + 仍比新增字段少 |

**反例（本次真实的）**：`(认领 日期 A)` 和 `(完成 日期 B)` 必须分开 ——
它们是**两个不同的人**，合并会丢信息。所以规则不是"尽量少字段"，是"同一个槽才合"。

## ⚠ 塞进去时的两个陷阱（都实测踩过）

### 陷阱 1：宽松正则会把旧内容误当成新值

第一版提取 sid 用了：

```js
body.match(/\(认领[^)]*?\s([\w-]+)\)/)     // ← 太宽松
```

对**公海任务**（`(认领 2026-10-09)`，没有 sid）→ 把**日期本身**当成了 sid，
看板显示出 `[会话 2026-10-09]`。

**修法：先锚住已知部分，再取新增部分**：

```js
body.match(/\(认领\s*\d{4}-\d{2}-\d{2}\s+([\w-]+)\)/)   // 日期是可选的"门"
```

**教训**：解析「追加在已有内容后面」的值时，必须用前面的固定结构当锚点，
不能用"最后一个 token"这种相对判据。

### 陷阱 2：原位重建时要把旧值原样搬回去

`upsertTask` 幂等更新时会**重建整行**。若重建时不搬旧认领段，
一次不带新参数的重复调用就会**把已写入的 sid 冲掉**（静默丢线索）。

```js
const claim = sid ? `(认领 ${today()} ${sid})` : (claimOf(raw) || `(认领 ${today()})`);
//                                                ^^^^^^^^^^^^^^^ 旧值兜底
```

**必须有测试钉住**「重复调用不带新参数，原值仍在」。

## 验证清单（照做）

1. **向后兼容**：不传新值时，输出与旧版**逐字相同**（有测试断言）
2. **幂等不冲**：重复写入不带新值，原值仍在
3. **搬运不丢**：归档/导出/拷贝后，新值还在
4. **正则不误伤**：旧数据（没有新值）不被错认成有新值
5. **破坏验证**：故意去掉「搬旧值」→ 测试必须变红
