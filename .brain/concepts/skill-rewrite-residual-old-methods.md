# 概念：skill 以旧文档为基底重写时，旧方法会残留成悬空引用

## 触发场景
把一份老 skill/文档升级成「以新工具(CLI/MCP)为主」的新版时，直接基于旧文档改，忘了旧内容里那些已被工具取代的「手工步骤」。

## ❌ 表现
- 旧文档的 `bootstrap.sh`、`./scripts/lint.sh`、`.sh 可执行文件`、手工建骨架等步骤，在新版里没删干净。
- 变成**悬空引用**：新文档说「没装 abs 退纯 skill 模式靠本文件全流程」，但本文件根本没给手工全流程——AI 照做会找不到方法。
- 更糟的是「不手工写 markdown」这类**过度承诺**：工具只生成骨架/落 source/检索，**深提炼(写 concept/entity 页)本质是判断力，工具不替**。一刀切"全自动不手写"与"深提炼必须手写"自相矛盾。

## 🛠 解法
1. 先列**实际工具能力清单**作基准（`abs` CLI 有哪些命令、MCP 有哪些工具）——不凭空写。
2. 逐行核对旧文档引用的每个命令/脚本是否真实存在；不存在的删或改指工具命令。
3. 明确**三层边界**：骨架/任务/暂存/检索/体检 = 工具做；深提炼(sources→concept/entity)= 手工(判断力)。
4. 全文搜残留旧方法词(bootstrap/.sh/scripts/手工建图/纯skill模式)，必须 0 残留。
5. 不写悬空承诺(如"没装X时用本文件全流程")——要么给全流程，要么删这句。

## 验证命令
`grep -n "bootstrap\|\.sh\|手工建骨架\|纯 skill 模式" <skill>` → 应 0 命中。
