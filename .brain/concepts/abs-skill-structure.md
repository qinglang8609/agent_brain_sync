# abs 结构与写作规范

从 SKILL 移出的长尾之一。SKILL 每轮进 system prompt，只留必读；这里放「写页时要对的格式」。

## 入口：先找图谱再分流

1. **找图谱**：只看**当前目录**是否含 `.brain/`，先 cd 到项目根。不向上搜索（会命中 `~/.brain`，把项目挂错）。
2. **没有图谱**：意图是沉淀或即将开工的长期任务（"帮我做 X / 开工 / 修 X"）→ 先 `abs init`；闲聊、一次性问句、明说不要建档、只读目录 → 不建档。
3. **分流**：

| 用户意图 | 走哪 |
|---|---|
| 总结经验 / 结束了 / "把这次记下来" | 收尾循环 |
| 查询坑 / "我上次怎么解决 X" | `abs query` |
| 体检图谱 | `abs lint` |
| 开新任务 / 继续开发 | 开场 Init Sync |
| 报 bug / 要求加功能 | 受理协议 |
| 意图不明 | 续 todo |

意图不明且项目有 `.brain/` 时，默认续 todo。

## 新需求受理协议（先方案 → 再登记 → 问开工）

用户报 bug 或要求加功能时先别动代码：

1. **总结方案**（一屏内）：准确复述需求（不确定就写明假设）；bug 给根因，功能给做法；要改哪些文件、怎么验证。
2. **登记 todo**：`abs todo add <id> --note "<需求+关键约束>"`；根因/取舍用 `abs todo note <id>` 追加成子项。
3. **问是否开工**：明确问一句，等确认再改代码。

**例外（可直接开工，回复里说明援引哪一条）**：用户已说"开工/直接做/修它"；一行级修字、纯查询、纯收尾沉淀；同一需求已登记且用户确认过。

## `.brain/` 怎么组织

`.brain/` 放项目根，一个项目一份，`abs status` 显示当前定位。

| 位置 | 放什么 | 硬约束 |
|---|---|---|
| `index.md` | `## Rules` 铁律 + 各类页清单 | Rules 一句一条不带链接，只有「违反会丢数据/静默失效/白干活」级才进，>42 字符或含链接被拒；清单每页一行 `- 页名 — 一句话`（页名写成双链） |
| `log.md` | 成果流水，倒序一行 | 只记成果，不记工具动作 |
| `todo.md` | 活看板 | 只有 `## Todo`/`## Done`；Done 必带 `【落地/否决/仅方案】`+`(完成 YYYY-MM-DD)` |
| `entities/` `concepts/` | 具名事物（`Docker.md`）/ 可复用规律坑（`docker-prisma-429.md`） | 拿不准默认进 `concepts/` |
| `sources/` `syntheses/` | 经验暂存 / 横向选型取舍 | sources 是暂存，提炼后删 |
| `sessions/` | 会话快照 + 当日归档段 | **一天只允许一个 `log-<日期>.md`**，多主题写多个 `##` 段 |

`todo.md` 行形态：`- [ ] [进行中] <id> <作者双链> — 说明 (认领 YYYY-MM-DD)`（标记还有 `[讨论中]`/`[滞留中]`；作者标记是使用者名）。`abs todo done <id>` 勾选并归位到 Done 日期组顶部，已勾子项随迁；超 3 天**且整天已完成**的组由 `abs wrapup` 迁进当天快照归档段（任一天还有未完成则整天不归档）。

`sessions/` 快照 = 正文 + `## 关联连接` + `## 🪝 Next Session Hook`（强制）+ `## 📦 任务归档`（机器写勿手改）。归档唯一动作 `abs todo archive`：已有快照只替换归档段，段外逐字保留；那天没有快照就建一个只含归档段的页；同日重复归档在段内追加。

### 容量纪律（写任何页之前过四关）

① **再命中** —— 下会话不知道这条会踩同坑/重做同决定？不会就不存，grep 得到的不记。② **单页上限** —— `entities/concepts/syntheses` 单页 <150 行且 <8KB，超了拆或外链。③ **sources 是暂存** —— 提炼后删并清引用。④ 能用一行链接代替新增整页吗？

## 按七层总结（总结前必读）

七层不是分类好看，是**检索权重不同**：L1 永不衰减，L7 几乎不参与。所以总结时必须先判层，判完直接落到位 —— 一律塞 sources/ 会让 44% 的知识按错误的权重参与检索。

| 层 | 判据 | 落点 | 怎么落 |
|---|---|---|---|
| L1 铁律 | 违反就必须停下 | index 的 `## Rules` | `abs capture --layer 1`（≤42 字、禁链接） |
| L2 规则 | 这个项目要遵守的做法 | `concepts/` + `layer: 2` | `abs capture --layer 2` |
| L3 工具 | 某工具怎么用、有什么坑 | `concepts/` + `layer: 3` | `abs capture --layer 3` |
| L4 认知 | 踩坑的根因与解法 | `concepts/` + `layer: 4` | `abs capture "…"`（默认） |
| L5 会话 | 这次做了什么 | `log.md` / `sessions/` | `abs log`（当天工作）/ `abs ingest`（一场会话） |
| L6 断点 | 双链词 | 不立页，机器自动抽 | 不接手写 |
| L7 混沌 | 还没想清的碎片 | `sources/` | `abs note`（capture 的 L7 已拒，同一个落点） |

判据不明时用 L4 —— 但**知道是工具经验就写 L3**：实测算过，本仓 52 页 concepts 里 23 页其实是 L3。

**`--kind` 是另一条正交轴**（借 cl​aude-mem 的 observation 类型）：`layer` 说「什么性质」，`kind` 说「起什么作用」。

| kind | 含义 | 何时用 |
|---|---|---|
| `gotcha` | 关键坑 | 踩了会白干、想不到的那种 |
| `decision` | 决策 | 记「当时为什么这么选」 |
| `tradeoff` | 权衡 | A 好但 B 也有理，最后选了哪个 |
| `howto` | 做法 | 这类事该怎么做 |

不传就不写（旧页留空，不强制补）。实测只有 `gotcha` 能靠 tags/标题机械识别，
另三类判据在内容里 —— 别拿关键词瞎猜。

**尾巴按 kind 分档**（`abs lint` 的 NO-TAIL）：`gotcha`/`howto` 必须有验证命令；
`decision`/`tradeoff` 写「当时依据什么选的」（取舍依据，不是可跑的命令）；
无 `kind` 的旧页保持原要求。理由：决策类知识天生没有验证命令，硬要写就是编。

## 知识页格式

统一 frontmatter：`tags / author / updated / status`。`tags` 首标签 ∈ `entity|concept|source|synthesis|session-log`；`author` 与 `entities/<name>.md` 同名。

**`status` 只有三个值**：`active` 当前有效（缺字段默认）；`draft` 待核实（`abs note` 默认，展示标 `[draft 未核实]`）；`superseded` 已被推翻，别再依据（`query` 默认隐藏）。推翻用 `abs supersede <页名> --by <新页>`（写 `superseded-by`；不写 `--by` = 单纯弃用；指向不存在的页会被拒）。历史必须留，核实后仍有效就改回 `active`。

- **每页必须有 `## 关联连接`**，用双链语法连相关页，解释写在 `—` 后（只写链点等于没链），只写链点等于没链。
- **命名即链接**：写 Docker 就找 `entities/Docker.md`，写 docker-prisma-429 就找 `concepts/`。不建别名层。
- **知识冲突**：不静默覆盖，加 `## 知识冲突`，两版都留、标来源时间，交人工裁决。
- 概念页骨架：`触发场景 / ❌表现(贴报错) / 🛠解法(根因+修复+验证命令) / 关联连接`。
