# 中文全文检索的四个实测坑

用 2-gram + FTS5 做中文检索时，逐层踩出来的四个问题。每个都是深度测试实测发现的，
都有测试钉住。

## 坑一：单字 gram 会连上一切

`bigrams` 同时产出 2-gram 和单字（为了「锁」这类一字查询能搜到）。但把这个集合
直接拿去做查询表达式，`不`/`存`/`在` 会命中任何一页。

**修**：查询侧单独一个 `queryBigrams`，只在「整条查询就是一个汉字」时才用单字。
存储侧保持超集 —— 要求的是「查询产出的每个 gram 存储侧都存在」，恒成立。

## 坑二：归一化分母取错了方向

bm25 返回**负值且越负越相关**，按 rank 升序排列（第一行最相关）。

```js
// 错：最后一条是**最不相关**的，其 rank ≈ 2e-6
const worst = Math.abs(kept[kept.length - 1].rank);
bright = Math.abs(r.rank) / worst;   // → 1168694！
```

实测输出过一行 165 万宽的亮度条。分母必须是 `kept[0]`（最相关那条）。

## 坑三：命中数门槛挡不住高频虚词

第一版用「命中 gram 数 ≥ 一半」。看着合理，但中文高频组合能绕过：
查 `zzzz不存在zzz` 时「不存在」切出 `[不存, 存在]`，命中 2/4 就达标。

**实测真实图谱的 gram 文档频率**：`验证` 84%、`关联` 79%、`连接` 79%、`触发` 78%。
这些 gram 没有区分度，却与稀有 gram 等权。

**修**：按文档频率加权 `w = log((总页数+1)/(出现页数+0.5))`，
覆盖率 = 命中 gram 权重和 / 查询 gram 总权重，低于 0.35 丢弃。
加权后 `[不存, 存在]` 只贡献 0.255，被正确拦下。

## 坑四：`({ g, ...r })` 解构把要用的字段吃掉了

为了消 lint 的 unused 警告，把 `map(({ g, ...r }) => ...)` 里的 `g` 改成 `_g`，
结果后面算覆盖率用的 `r.g` 变成 `undefined`，命中数恒 0 —— 亮度全错但**不报错**。

**判据**：解构排除字段时，确认后面没有代码再引用它。这类错误靠 lint 抓不到，
只能靠「算出来的值明显不对」发现。

## 验证

`node --test test/brain-graph.test.js`（35 个用例）。关键几条：
- 「搜索：不存在的词不能靠单个 gram 误命中」
- 「亮度必须在 0.3~1.0 之间，不能出现天文数字」
- 「高频虚词组合不能靠命中数凑够门槛」
- 「superseded 页不出现在检索结果里」

反向验证：把任一修复改回去，对应测试必须变红。
