# 加了新机制，旧判据要重新过一遍

旧判据在新机制下不一定还成立，但**它不会报错**——只会安静地把新东西埋掉。

## 触发场景

- 新功能产出的东西，和旧功能假设的粒度/命名/生命周期不一样
- 旧的「跳过」「判重」「缓存命中」逻辑仍在跑
- 两者都「工作正常」，只是结果少了一块

## ❌ 表现（实测两次，同一轮）

**一、`summon` 把新会话页当成「整天已总结」**

`daysWithSnapshot()` 只做一件事：从 `.brain/sessions/*.md` 的文件名里抠日期，抠到就认为那天整理过了。

旧世界只有一个文件带日期：`log-<日期>.md`（人写的一天流水）。按天跳过完全正确。

新世界多了 `session-<日期>-s<id8>.md`（`abs ingest` 的产物，**一场会话一张**）。于是：

（形状又变了一次：2026-11-08 起摘要并进当天的 `log-<日期>.md`，按文件名抠日期这条路走不通了，
判据改成读页内 `挂钩: session=<id>` 逐场判。**结论没变，只是实现要跟着数据形状再改一次** ——
这正是本页要教的那件事。）

```
一天三场会话 → 落了 1 场的页 → summon 报「未总结 0 个」
                              → 另外两场被永久埋掉
```

实测真实项目有 **14 天**存在多场会话，最多的一天 **10 场**。这个 bug 的实际影响面比想象大。

**二、`ingest` 落了页却不记账**

原设计「只有 `--mark` 才写账本」，理由是「生成页不等于人读过」。
于是已落页的会话**永远停在「未总结」名单里**，`summon` 反复催同一场。

```
$ ls .brain/sessions/          → session-2026-11-04-saaaa0001.md  （页存在）
$ abs summon                   → 未总结 3 个（其中包含已落页的那场）
```

**催一个已经存在的东西，比不提醒更糟**——它训练人忽略这条提醒。

## 🛠 做法

新机制上场时，把「旧的跳过/判重逻辑」逐条列出来问：

1. **它的粒度还对吗？** 旧的是「一天」，新的是「一场」，那按天判重就不再生效。
2. **它的前提还成立吗？** 旧的是「生成页=还没读」，新的是「生成页=已提取」。
3. **它会不会静默少给东西？** 会 — 那是最难发现的一类，因为没有任何报错。

具体修法：

```js
// daysWithSnapshot：只认整天快照
if (f.startsWith('session-')) continue;   // 一场一张的页，不代表整天

// ingest：落页即记账
// 判据从「人读过没有」改成「这场会话有没有对应的页」
// 「读没读」由 load 的未填提醒负责 —— 那是另一件事
```

## 判据

**「跳过」是一句关于粒度的断言。** 写它的时候，要能说出「它跳过的到底是什么单位」——
一旦新东西的单位不同，这句话就变成假的，但它不会自己失效。

## 验证

```bash
node --test test/summon.test.js   # 单场页不算整天快照 + 旧行为（log-<日期>）不变
node --test test/ingest.test.js   # 落页即记账，不给 --mark 也算
```

端到端实测（2026-11-05，一天三场会话）：

```
初始   未总结 3
落1场  未总结 2 · 已总结 1
落3场  未总结 0 · 已总结 3   三张页都在
```
