# 规律进化的三个环节：采集 / 消化 / 生效

## 触发场景
评估「图谱能不能让 AI 进化」时，或发现**同类坑反复发作**时。
不要凭感觉答「有积累」，用 git 查真实路径。

## 判据：进化的可检验定义

> **同类坑族的复发间隔，应随制度增加而拉长。**

这是唯一不靠感觉的判据。做不到 = 在累积文档，不在进化。

**2026-09-15 实测（本仓）：没进化**

| 坑族 | 复发 | 趋势 |
|---|---|---|
| 静默失效 | 09-10 ×2、09-13 ×2、**09-15** | 反而加快 |
| 版本/副本漂移 | 09-12、09-13、**09-15** | 没拉长 |

## ❌ 表现：三环节只有一个在工作

| 环节 | 机制 | 实际状态 |
|---|---|---|
| **采集** | hook 自动写日志 | ✅ 机械可靠（09-08~12 五天 105 条 log） |
| **消化** | 人工提炼 concepts | ⚠️ 有产物但靠自觉（sources 积压 14 > 10） |
| **生效** | ？ | ❌ **根本不存在** |

**根因不是"没学到"，是"学到了没用上"。** concepts 写完就躺着，没有任何东西保证
它在下一次动手前被想起 —— 只有关键词命中才出现。

## 🛠 核心矛盾：能生长的读不到，读得到的不生长

- **Rules** = 全系统唯一「强制送达」通道（`abs load` 每次原样全量输出，代码里明确不折）
- **concepts** = 持续生长，但只在查询命中时出现

实测（git 实证，非推测）：

```
09-08 ─ 09-12   Rules 区【不存在】  经验全部进 concepts/（5 天涨 20+ 页）
09-13 4a56168   Rules 诞生，一次性注入 16 条  ← commit: "结构重建 + Rules 工具化"
09-14 c86174c   17 → 12（重写措辞）
09-15 931b984   12 → 14（用户当场提的 2 条）
09-15           14 → 14（本次会话 0 新增）
```

**14 条里 13 条来自两次集中人工注入；只有 1 条（hook 节流）从具体 bug 自然长出。**

→ **Rules 不积累，它是 09-13 人工灌满后就没再进过货。**
09-13 那次把 concepts 的规律**单向上行**提升进了 Rules，**但没留下让后续经验再走一次的机制**。

## 🛠 解法：补上「生效环」，走已有的强制通道

### 1. 输入端：收尾循环插入 Rules 判定
判据要从「够格就加」（条件，可无限推迟）改成
**「够格却不加 = 这条教训下次不会送达」（后果，有明确代价）**。

### 2. 用「提议」而非「直写」
Rules 门槛严（42 字符、无链接、无解释）是**对的**，但意味着 AI 判「够不够格」很主观。
→ **AI 只负责在正确时机提议，拍板权交回用户**（符合「工具不替你判断」）。
形如：`[T-提议] 本次够格进 Rules: 「…」  加？abs rule add "…"`

### 3. 反面：不要让 lint 报「Rules 长期无新增」
那是**又一个「靠提醒工作的功能」**，违反本仓已有的硬规则
「靠提醒才能工作的功能，该删不该补」。**明确不做。**

### 4. 写入侧定结构：结构由代码给，内容由人填（2026-09-15 实证）

上面三条都在讲「怎么送达」，但更根本的一层是**写入时就别写坏**。

**实证对照（同一个项目，两种命运）**：

| | 骨架写在哪 | 结果 |
|---|---|---|
| `sources/` 页 | **代码里**（`cmdNote` 的模板） | 结构整齐 —— 每页都有 `## 记录` + `## 关联连接` |
| `concepts/` 页 | **skill 的文字里**（一行带过的「骨架：A/B/C」） | **无任何代码写入路径** → 26 页里 2 页完全没尾巴，首版判据还误报 7/11 |

→ **有代码执行点的 = 生效；只在 skill 文字里的 = 看运气。** 这条规律在本仓反复成立
（Rules 判定塞在附属从句 → 长期 0 新增；单列成一步 → 才有机会被执行）。

**解法**：给 `concepts/` 页补一个写入入口 `abs concept <slug> --title …`，
生成带好四段位置（触发场景 / 表现 / 解法 / **验证**）的骨架并自动登记 index。

**关键边界（别越界）**：它**只给结构，不给内容** ——
「这条值不值得留 / 该新建还是并入已有页」仍是判断，仍归人。
**结构可以代码化，判断不能。** 这与 skill 里「深提炼必须手工」的分工一致。

**配套**：判据（lint `NO-TAIL`）要能识破「有标题但没内容」的未填骨架，
否则骨架建完即"自动合格"，永远没人填 —— 判据必须看**段内有没有真内容**（占位注释不算）。

## 验证命令
```bash
# 查 Rules 真实积累路径（别靠印象）
git log --format='%h %ad %s' --date=short --reverse -- .brain/index.md
# 查某条 Rule 的引入 commit
git log -S'<规则片段>' --oneline -- .brain/index.md
# 判「有没有进化」：看同类坑复发间隔，不看文档量
ls .brain/concepts/ | grep -iE "silent|drift|stale"
```
