# 自动登记 todo 的设计约束：靠指引不如靠 hook，但 hook 要防三件事

## 触发场景
「任务登记不及时」——agent 干了一堆活忘了登记，换会话时断点全丢。
先试过**往 system prompt 注入常驻指引**（promptGuidelines），失败；改用 **hook 自动登记**。

## ❌ 为什么"指引"这条路走不通（实测 414 次有痕，行为没变）

指引写的是「动手前用 task 工具登记 / 完成立刻 done」。它假设 agent
**已经决定"我要开一个任务"** —— 但排查类工作的心理状态是：

> 「我先看看怎么回事」→ 看明白了，活儿已经干完一半。

**没有清晰的"开工时刻"，提醒再多也没用。** 指引是正确的但没落在触发点上。

**通则：靠"提醒 agent 记得做某事"的功能，多半该改成"宿主替你做了"。
提醒需要被提醒者先有动机，而 hook 不需要。**

## 🛠 hook 侧要防的三件事（都踩过）

### ⓪ 时机：别在"一按回车"时登记（用户实报）
初版挂在 `before_agent_start` —— **用户一按回车就登记**。结果：

> 「我说一句话，可能还没产生需求，就添加到 todo 了」

用户的输入常常是**探索/提问/讨论**（"能不能加个 X"、"为什么是这样"），
离"一件要做的事"还很远。在那一瞬登记，等于把**对话**当成**任务**。

**改法**：挪到**第一次真改文件**（`tool_call` 的写类工具）——
那一刻"已经动过文件"就是最可靠的"这真是件事"的证据。

```
你："能不能加个 X"   → 不登记（只是问）
你："帮我把 X 加上"   → 不登记（还没动手）
我：（开始改代码）    → ✔ 登记 + 断点
```

**连带设计**：登记时要用用户指令抽关键词，故 `before_agent_start` 仍需
**记住**指令文本（模块级 `pendingPrompt`），只是不登记。
抽不出关键词时（寒暄后开始干活）用**断点里的文件名兜底** —— 别白白丢弃。

> 通则：**自动登记要挂在"不可否认的行动"上，不是"可能的意图"上。**
> 用户的每一句话都是输入，但只有动过手才是事实。

### ① 刷屏：粒度必须"一会话一条"，不是"一动作一条"
一个会话可能改 20 个文件。若一文件一条 → 看板被垃圾淹没，
违 [[read-side-output-must-not-scale]] 的同类原则（读取侧不得随规模增长）。

**做法**：用**会话 id 当幂等键**，同会话只更新断点。
首轮登记，后续只 `setBreakpoint`。

### ② 把"提问"当"指令"（用户实报）
用户问「**为什么任务是这个啊**」，被抽成任务登进了看板 ——
**把用户的疑问变成自己的待办**，很荒唐。

**做法**：抽关键词前先过滤疑问句：
```js
if (/[?？]\s*$/.test(s)) return null
if (/(为什么|为啥|怎么|如何|什么是|能不能|是否|吗$|呢$)/.test(s)) return null
```
外加原有的寒暄过滤（在吗/继续/abs/好的…）。

> 判据：**登记的是"让我动手的事"，不是"出现在对话里的话"。**

### ③ id 人认不出（用户实报）
初版 `id = auto-<会话uuid前16位>` → 用户看到 `auto-01a10b96-372d-71` 认不出是什么。

**做法**：**id 用指令关键词**（给人看），**会话 id 退成隐藏幂等键**：
```markdown
- [ ] [进行中] auto-修复面板不刷新 [[fanchao]] — 修复面板不刷新 (自动登记 01a10b96-372d-71)
                ↑ 给人看的 id              ↑ 描述          ↑ 机器用的幂等键
```
**连带坑**：`sweep`（收尾清理）不能再按 `auto-` 前缀认领 ——
人工也可能起出 `auto-fix-x` 这种名字，按前缀会**误杀真任务**。
判据改成**按「自动登记」标记**认领。

## 完整时机表

| 时机 | 动作 | 限流 |
|---|---|---|
| `before_agent_start` | **只记住**用户指令，不登记 | — |
| `tool_call`（写类工具） | **首次登记**（此刻才算真开工）+ 落断点 | 只记第一次写（不是流水账） |
| `agent_end` | 推进断点「本轮到哪」 | 仅在本会话动过文件时 |
| `agent_end` | 推进断点「本轮到哪」 | 仅在本会话动过文件时 |
| `session_shutdown` / wrapup | 自动条目标 done | 结语 `【仅方案】`，不冒充 `【落地】` |

**写类工具白名单必须含 bash** —— 大量修改走 `sed -i` / 重定向，
漏了它会静默关掉整个功能（见 [[opencode-inject-channel-verdict]] 的同源教训）。
bash 还要追加甄别（`>`、`sed -i`、`tee`、`rm`、`mv`…），否则 `ls`/`git status` 也记断点。

## 开关与隔离
- `ABS_AUTO_TASK=0` 全关（对齐既有的 `ABS_TODO_GUIDE` / `ABS_TODO_PANEL` 风格）
- 扩展的 `ABS_BIN` 支持 `ABS_BIN_PATH` 环境变量覆盖 —— **否则测试无法隔离**
  （安装时替换成的 `stableBinPath` 优先指向全局副本，测试会写进真库）

## 验证

```bash
node --test test/auto-task.test.js        # 14 例：抽词/幂等/收尾/开关/边界
node --test --test-name-pattern="自动登记" test/plugin-behavior.test.js  # 9 例：真驱动事件
```

必查用例：疑问句不登记 / 一会话一条 / 人工任务不被 sweep 误杀 / 只读 bash 不记断点。
