# agent_end 不是会话结尾

`agent_end` 听起来像「会话结束」，实际是**agent 这一轮回复结束**。用户只发一句话、
助手回一句，它就会触发。

## 触发场景

把收尾提示、状态沉淀、总结注入挂在 `agent_end` 上，并假设「它只在人真正收工时来」。

## ❌ 表现

2026-09-21 / 09-22 实测两次被用户当面指出：

> 每次会话会突然出现 `[abs] 本会话改过文件，.brain/ 今日无记录`，然后任务中断

> 但是刚刚的会话**才聊了一句话就触发了**，也就是说 pi 的结尾并不是我们想象中的结尾

症状是：聊一句就被打断一次，提示语反复出现，反而干扰正常工作。
当时为了压住它，加了「每会话一次」的节流 —— 那是**在错误的理解上打补丁**。

## 🛠 解法

判据只有一条：**不要用「事件名」推断「时机」。**

要「真正收工才提醒」，不能挂 `agent_end`，必须自己判两件事：

1. **本会话真的干过活**（改过文件 / 有工具调用足迹），纯聊天不打扰
2. **今天真的还没有记录**（`log.md` 无当日条目），已有就放行

这两条现在写在 `teardown-check` 的条件①③里，并叠了 `stop_hook_active` 与
会话级 mark 双重防重入 —— 因为官方 `stop_hook_active` 有已知不传播的 bug，
单靠它会在同一 turn 内重复 fire。

## 验证

改 hook 触发逻辑后，用「一句话会话」实测：
发一条无实质内容的短消息，助手回一句，**不应**出现收尾提示。
反向验证：真改了文件再跑，应当出现——不出现说明条件判得太死。
