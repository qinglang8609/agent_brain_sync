# 读取侧输出不得随规模增长

## 触发场景
一个"开机读状态"的命令（`abs load`）或"给人看的视图"，把某个**无上限增长**的数据
原样打印出来。症状：项目越用越久，同一个命令吐回的上下文越多，直到把窗口塞满。

## ❌表现
本项目**同一个根因连续踩中三次**，每次都是"这段数据会无限长大，却被全量打印"：

| 区块 | 占比 | 膨胀源 | 修复 |
|---|---|---|---|
| `## Done` 区 | load 输出的 68.8% | 完成的任务永不删除 | 折成按日期计数 |
| `log` 最近 5 条 | ~2.9KB | 单条日志写到 800 字符 | 每条 `clip(220)` 按语义边界收口 |
| `index` 页面清单 | load 输出的 64%（**修完 Done 后它成了新的大头**） | 每页一句话描述，图谱只增不减 | 各分区折成页数计数 |

实报：用户另一台机器**单次 `abs load` 吃掉 ~40% 上下文**。
严重性在于它是**静默的** —— 命令成功、输出"看起来正常"，只是慢慢地越来越难用。

> 注意第三个：**修完最大的那个，第二大的就顶上来了**。占比是相对的，
> 要盯的是"这一项**会不会随规模增长**"，不是"它现在是不是最大"。

## 🛠解法（根因 + 修复 + 验证命令）
**根因**：读**状态**的入口，承担了读**归档**的职责。两者生命周期完全不同 ——
状态是有界的（当前在做什么、卡在哪），归档是无界的（历史只会更多）。

**修法（一律在读取侧收口，不动写入侧）**：
- 会无限增长的数据，在"给人看/给 AI 看"的视图里**只给摘要或计数**，
  明细走**显式**逃生口（`abs todo --full` / `abs index`）。
- 判断"哪些该折"的标准是**增长性**，不是当前大小：
  路线（Roadmap）有界 → 原样保留；页面清单无界 → 折叠。
  折错了（把有界的内容也折掉）等于把命令废掉。
- 收口要收在**读者真正用的那个函数**里（`collapseDone`/`collapseIndex`），
  CLI 与 MCP 两条路径共用它 → 一处修、两处生效。若在调用点各写一遍，必漂。

**验证命令（必须证明"不随规模增长"，不是"变小了"）**：
```bash
# 造 400 条 Done / 60 条 concept，输出应与小样本基本一致
node -e "...写入大量数据..." && node bin/abs.js load | wc -c
```
回归测试断言的是**增长率**（`bigOut/smallOut < 1.3`），不是绝对值 ——
写死字节数的测试会随文档改动而碎。

## 推广：判别式
> 拿到一段要打进上下文的输出，先问：**这段会不会随项目历史/数据量增长？**
> 会 → 只给计数/摘要 + 逃生口。不会 → 原样给，别过度折叠。
