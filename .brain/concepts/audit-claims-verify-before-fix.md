# 审计清单也是待证证据：逐条最小探针确证后再改

## 触发场景
拿到一份**第三方产出的问题清单**（另一会话的审计报告、code review 意见、issue 列表、上级列的风险项），准备按它开修。

## ❌ 表现
清单读起来像事实（带文件名、行号、代码片段、命令实测输出），于是**直接照着改**。
本次 6 条里 **2 条部分失实**：

| 审计原话 | 真跑后的实况 |
|---|---|
| 「`done` 分支只读 `as`、忽略 `note`」 | 比这严重：`note` 不丢，而是**静默盖成【落地】**（把用户结语吞了还写在盘上） |
| 「用户可见输出带零宽字符（U+200B）」 | 属实（我一度误判成 mojibake） |

**先入为主地相信清单 = 用别人的假设当自己的证据。** 与「自造证据」是同一个病的镜像：
那边是自己编输入，这边是**不验证别人的输入就动手**，两者都把失实前提静默带进代码。

## 🛠 解法
**逐条最小探针确证/证伪，再动代码** —— 探针要短到能在一次调用里跑完：

| 类型 | 最小探针 |
|---|---|
| 「某参数被忽略」 | 用该参数调一次函数，**看落盘文件**（不只看返回值） |
| 「某分支不可达」 | 读 `FLAG_SPEC`/schema 定义处，确认键**根本没声明** |
| 「字节级/编码类断言」 | 用**字节级工具**复核（Node 里 `str.includes('\u200b')`；不要靠 `cat -v` 目视判 mojibake） |
| 「判据不一致」 | 抽出各副本的正则/条件，**并排跑同一组输入**看结论是否分叉 |

两条纪律：
1. **别在探针里加代码**：确证用 `node -e` 直调导出函数、或临时目录造数据，不污染仓库。
2. **探针结论要落到 todo 断点**（`abs todo note`），否则下个会话只剩「审计说 X」而不知道 X 验过没有。

## 验证
本轮 6 条全部先探针后改：
- `cmdTask({action:'done', id, note:'结语内容'})` → 落盘行是 `【落地】`，`结语内容` 一个字没进 todo.md（确证「静默盖」，比审计描述更准）。
- 正则对照脚本（同一组 note/dev 输入跑 store.js 与 pi 两份判据）：旧判据 `note-only=true`（误判已收尾），pi 判据 `false`（正确）→ 确证三宿主判据分叉。
- Node 扫 `bin/abs.js`：`行60(3处)`、`行221(3处)` 真实 U+200B，用户复制 help 里的宿主名必坏。
- 改完端到端：MCP 走标准协议做到 `as=仅方案` 落盘；CC 路径真进程 `push:`；385 test 全绿。
