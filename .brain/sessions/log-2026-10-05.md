## 今日主题：宿主升级适配 + 自动登记实验（做完又删）

今天发了 **7 个版本**（1.13.3 → 1.14.0 → 1.14.1 → 1.15.0 → 1.15.1 → 1.15.2 → 1.15.3），
20 个 commit。三条主线：

### 一、宿主 API 升级适配（用户实报）
- **op​encode v2 插件加载失败** —— v2 把插件契约从 `{id,server}` 改成 `{id,setup}`。
  模板/全局副本/宿主落点**三处同改**；只改落点会被下次 `abs install` 静默覆盖。
- **skill 不自动触发** —— 两个独立杀手叠加：description 写成主题描述而非触发条件；
  且 `~/.agents/skills/` 的陈旧副本被 pi 的 symlink 指着、绕过 install 管理
  （这是"改了三轮没生效"的真因）。

### 二、hook 侧 todo 自动登记（新增功能，三版迭代）
治「任务登记不及时、换会话断点丢失」。先试过 system prompt 常驻指引
（实测 414 次有痕）**但行为没变** —— 指引假设 agent 已决定"要开一个任务"，
而排查类工作没有清晰的开工时刻。改由 hook 替 agent 做。

三版迭代（每版都是用户实报驱动的）：

| 版本 | 用户实报 | 改法 |
|---|---|---|
| 1.14.0 | （初版） | 一会话一条 + uuid 当 id |
| 1.14.1 | 「我说一句话还没产生需求就添加到 todo 了」 | 登记点从"一按回车"挪到"真改文件" |
| 1.15.0 | 「关键词还是不对，不能像 fix-skill-trigger 那样吗」 | 改 TBD 占位 + 新增 `abs todo rename` |
| **1.15.2** | **「卡顿」+「看板冒出大量 auto-TBD-xxx 待命名」** | **整体移除该功能** |

**结局：功能被删。** 不是参数没调好，是方向错 —— 三次迭代都在让机器做需要理解的事
（判断"这是件事"、起名字、记断点）。详见 [[auto-todo-register-design]]。
保留两处有价值的产物：面板重绘修复、`abs todo rename` 通用能力。

### 三、abs todo 全流程实测（用户要求）
8 子命令 + 11 组边界，用全局版本跑两轮全通过。**逼出一个真 bug**：
`archive --keep-days 0` 踩 JS falsy 陷阱被静默当成"没传值"（`0 || 3` → 3）。
