今天发了 **5 个版本**（1.13.3 → 1.14.0 → 1.14.1 → 1.15.0），19 个 commit。
两条主线：

### 一、宿主 API 升级适配（用户实报）
- **op​encode v2 插件加载失败** —— v2 把插件契约从 `{id,server}` 改成 `{id,setup}`。
  模板/全局副本/宿主落点**三处同改**；只改落点会被下次 `abs install` 静默覆盖。
- **skill 不自动触发** —— 两个独立杀手叠加：description 写成主题描述而非触发条件；
  且 `~/.agents/skills/` 的陈旧副本被 pi 的 symlink 指着、绕过 install 管理
  （这是"改了三轮没生效"的真因）。

### 二、hook 侧 todo 自动登记（新增功能，三版迭代）
治「任务登记不及时、换会话断点丢失」。先试过 system prompt 常驻指引
（实测 414 次有痕）**但行为没变** —— 指引假设 agent 已决定"要开一个任务"，
而排查类工作没有清晰的开工时刻。改由 hook 替 agent 做。

三版迭代（每版都是用户实报驱动的）：

| 版本 | 用户实报 | 改法 |

## 🪝 Next Session Hook

**必读**（下会话开工前看这里）：

1. **今天的功能全在 v1.15.0**，四宿主已装。若用户报"没生效"，先确认 pi 是否重启过
   —— 扩展是**进程启动时加载**的，改文件不重启等于没改（见 concept `deploy-artifact-copies`）。

2. **看到 `auto-TBD-<会话>` 占位 → 第一件事是改名**：
   ```bash
   abs todo rename auto-TBD-<会话> --note "fix-xxx"
   ```
   名字要说清**在干什么**（像 `fix-skill-trigger`），不是抄用户原话。
   这条已写进 SKILL.md；占位条目由 hook 自动收尾（结语【仅方案】）。

3. **待办（未做）**：`[Rules 提议]` 已输出但用户未确认 ——
   「别让机器猜它没有的信息 —— 抽不出的就占位，不要兜底」。
   下会话若用户说"加"就 `abs rule add`，说"不加"就作罢。

4. **可观察点**（判断自动登记是否真的好用，别只看实现）：
