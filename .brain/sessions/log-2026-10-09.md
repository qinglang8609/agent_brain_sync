## 二、会话 sid 归属（session-scoped-tasks）

需求：同机开两个 pi，todo 是同一份，A 在做的事 B 也去做（任务串了）。

**核心设计：塞进已有字段，不新增**
```
- [ ] [进行中] T1 [[fanchao]] — 描述 (认领 2026-10-09 01a11eae)
```
- 归档是**整行搬运** → sid 自动跟着走，**归档代码零改动**
- 6 处解析里 5 处用通配 `\(认领[^)]*\)` → 零改动；只有 hook 那处写死格式要改

**双通路**（LLM 平时走 MCP）：
- CLI `abs todo start <id> --session <sid>`
- MCP `abs_task { session }`
- hook 注入 `[会话] 本会话 id = xxx` 让 LLM 自己填（**用户定：不搞进程探测**）

**看板区分归属**：`[本会话]` / `[会话 01a11f2a]` / 不带标记=公海

**认领≠完成**（用户追问后补）：两个 sid 都留
```
- [x] T1 … (认领 2026-10-09 01a11eae) 【落地】 (完成 2026-10-09 01a11f2a)
```

**实测三轮纠正**：
1. 第一版做成「隐藏别人的任务」→ 用户：不是隐藏，是标出来让它自己判
2. 第二版加了 `<sid>.md` 信标体系 → 用户：sessions/ 只放 todo 归档，别污染
3. 第三版想搞进程探测拿 sid → 用户：**让 LLM 自己给**

方案 `docs/plans/20261009-session-scoped-tasks.md`，经验 `concepts/reuse-existing-field-over-new-one.md`。

## 四、查出但未解决的问题

### 1. hook 插件是拷贝不是软链（已记入 Rule 17 覆盖）

`abs install` 把 `hooks/abs.pi.ts` **拷贝**到 `~/.pi/agent/extensions/abs.ts`，
改源码后不重装就不生效。本次差点带着旧版发版。

### 2. flaky：plugin-behavior「只首轮送一次」（另开任务）

并发负载下低频偶发失败。已排除：
- 单文件跑 5 + 12 次：全绿
- 6 进程并发 × 4 轮 = 24 次：0 复现
- in-process 定向压测 300 次：0 异常
- 干净 HEAD 全量 6 次：干净；我的版本 6 次抖 1 次

**缺口：始终没抓到断言细节**（不知是 `首轮≠1` 还是 `二次≠0`）。
下一步：先在断言失败时打印 `loadPending` / `loadInjected` / `promptGuidelines` 全量，
让**一次运行**就能定位，别再靠"跑 N 次碰运气"。

### 3. pi TUI 崩溃（非本项目问题）

`Terminal width: 35`，而 todo 面板标题行渲染宽度 36 → pi 抛异常退出。
日志明说 "custom TUI component not truncating its output"。
**是 pi TUI 的 bug + 终端过窄**，与 abs 数据无关。

## 五、排查方法的教训（值得单独记）

**「跑 N 次碰运气」是错的排查方式。** 本次为抓 flaky 跑了 24 + 300 次都没复现，
单次 `npm test` 就要 15 秒（`cli.test.js` 有 151 次 spawn 子进程）。

**正确做法：在测试内部加强诊断**，让失败时一次就吐出根因，
而不是在外面空转几十次。
