# 会话 2026-09-10 — 修 Co​dex 安装崩溃 + 补收尾自动化（并暴露"自动化形同虚设"）

## 一、起因：Co​dex 装不上

用户在其他机器 `abs install` 到 co​dex 时报 `cfg.hooks.filter is not a function`。

**根因**：`src/install.js` 把 Co​dex hooks 写成扁平数组 `{hooks: [{event, command}]}`，
而 Co​dex 真实 `~/.co​dex/hooks.json` 是对象形态 `{hooks: {EventName: [{matcher?, hooks:[{type,command}]}]}}`
（与 Cl​aude `settings.json` 同形）。目标机该文件已是对象 → `.filter` 崩。

**修复**（`src/install.js`）：
- 安装改对象形态，按事件合并、保留既有 hook（moshi 等）、幂等重装；
- 历史扁平数组形态**迁移**成对象，不丢用户 hook；
- **卸载侧原来只处理扁平数组** → 对象形态的 hook 永远删不掉，一并修（两形态都处理，空事件整删）。

测试：新增 3 例（对象形态幂等重装+共存+卸载只删 abs、扁平数组迁移）。发布 0.1.1。

## 二、真正的反馈：abs 的自动化形同虚设

用户指出：**"你刚刚做完的这个工作还是没有自动化到 abs，abs 的初衷就是无人值守自动总结自动 todo"**。

查证（铁证）：
- `.brain/todo.md` 停在 **2026-09-09 04:44**，`.brain/log.md` 停在 **2026-09-09 04:54**；
- 本会话 2026-09-10 10:00–10:53 干了大量实事（修 bug/发布），**`.brain` 一字未写**；
- `~/.abs/log/hooks.log` 本会话只有 `session_start`×5 + `session_shutdown`×1，**零条收尾**。

**根因（两层）**：
1. **事件缺**：pi 扩展只挂 `session_start`/`session_shutdown`。`session_shutdown` 只在**退出 pi** 时触发，
   正常干活到一半永远等不到收尾信号（Cl​aude/Co​dex 侧有 `Stop` 事件，pi 侧没有对应物）。
2. **机制被动**：`abs wrapup` 只往 `wrapup.log` 写一行快照。它"记了有滞留"，但**没有任何机制让 agent 真的去收尾**
   —— 下会话靠 `abs load` 顶出滞留，前提是"你还记得跑 abs load"。收尾仍靠自觉，而自觉不可靠。

**修复（真自动化 = hook 主动推，不靠自觉）**（`src/install.js` 的 `piPluginSource`）：
- pi 扩展挂 **`agent_end`**，满足条件时 `pi.sendUserMessage(收尾指令, {deliverAs: 'followUp'})`
  **把 agent 推去走收尾循环**（不是只写日志）。
- **触发条件收窄**（否则每轮都吵）：本会话真改过文件（`write`/`edit`/非只读 `bash`，
  只读 bash 用 `READONLY_CMD` 排除 `ls/cat/grep/git status...`）+ `.brain` 存在 + `log.md` 今日无记录；
- **每会话最多一次**（`teardownNudged` 标志）；已收尾/无图谱则不打扰。

**踩坑**：注入文本写在 JS 模板字符串里，`\n` 和 `\"` 被外层模板先吃掉，生成出跨行裸字符串
（语法坏）。须双写 `\\n` / `\\\"`。验证方式：从生成的 `abs.ts` 抠出字面量 `eval` 看最终渲染。

测试：新增 1 例断言挂 `agent_end`/用 `sendUserMessage`/有节流与判定函数。发布 0.2.0。

## 五、op​encode 侧：插件从未触发过（第二半）

用户说"继续"后接着补 op​encode。查证发现**比预想严重**：

**op​encode 插件从来没触发过** —— `grep -c "opencode:" ~/.abs/log/hooks.log` = **0**。

**根因**：模板写成 `event: async ({ name }) => {...}`，但 `@op​encode-ai/plugin` 的真实类型是
`event?: (input: { event: Event }) => Promise<void>`，事件名在 **`event.type`**。
→ `name` 恒 `undefined` → `includes()` 恒 false → **静默失效，无任何报错**。
（事件名也错：真实是 `session.created`/`session.idle`/`session.deleted`，不是 `session.start`/`session.end`。）

**修复**（据官方 `.d.ts` 实核，非凭印象）：
- 签名改 `event: async ({ event })`，从 `event.type` 取事件名；
- 补 **收尾注入**（与 pi 同策略）：`session.idle`（= 每轮结束）时经
  `client.session.promptAsync({ path:{id:sessionID}, query:{directory}, body:{parts:[{type:'text',text}]} })` 注入收尾指令；
- 真改过文件由 **`tool.execute.after`** 观测（`write`/`edit`/`patch` 类工具名）；
- 同四条件收窄 + 每会话一次节流。

**验证**：
- 生成插件语法 OK；行为级模拟测试 **8/8**（只读不注入/写后注入一次/再 idle 节流/今日已收尾不注入/无图谱不注入/日志落痕）；
- 与官方 `Plugin` 契约校验通过（`(input) => Promise<Hooks>`，返回 `{event, 'tool.execute.after'}`）；
- 已装到真实 `~/.config/op​encode/plugins/abs.ts`（旧版备份）。

新增 2 条回归测试（断言挂对事件、用对签名、不得用 `({name})`）。发布 **0.3.0**。

## 八、可观测性：补 seen 痕（第四半）

排查中发现一个**无判断依据**的问题：插件只在**真注入**（nudge）时写日志，
所以看 `hooks.log` 时**无法区分三种状态**：
① 事件根本没触发（扩展没加载）② 触发了但被守卫拦下（今日已收尾/无图谱/只读）③ 真注入了。

本会话（11:25 重启后）跑了大量 turn、大量 write/edit/bash，
`agent_end` 却**零痕** —— 分不清是“扩展没跑”还是“跑了被拦下”（实际是后者，
因为 `log.md` 已有今日记录）。

**修法**：首次 `agent_end` / `session.idle` **无条件**写一行 `seen` 痕（只记一次，不刷屏）。
→ 三态变为：**无痕** = 未触发；**有 seen 无 nudge** = 被拦下；**有 nudge** = 真注入。

**通则**：判断“机制是否生效”的日志，必须有一条**不受任何守卫影响**的痕。

新增 2 条测试（断言被拦下时仍有 seen 痕、且只记一次）。共 **146 测试绿**。发布 **0.5.0**。

## 十一、补 abs update / --version（真收尾）

用户报："在另外一台电脑上 update，没发现新版本"。

**根因（不是缓存、不是网络）**：**`abs update` 命令根本不存在**。
跑它会输出 `未知命令: update`。同理 `abs --version` / `-v` 也不存在 ——
用户既无法查版本，也无法通过 abs 升级，只能自己知道去跑 `npm i -g`。

这是真缺口：用户的心智模型是"abs 自我管理"（install/uninstall 确实在），
但升级路径断了。

**修复**：
- `abs --version` / `-v` / `version` → 读包 `package.json` 输出版本；
- `abs update` → `npm view` 查最新 → 对比当前 → 有新版则 `npm i -g @latest`
  → **自动重跑 install 刷新四宿主 hook/skill**（hook 脚本烧的是绝对路径 + 模板快照，
  升级后不刷新就用不上新代码）；网络/代理失败时给明确的手动命令。
- help 列出两者（自我管理命令必须可发现）。

新增 2 条测试（三种 --version 别名输出包版本；help 含 update/--version）。共 **148 测试绿**。
