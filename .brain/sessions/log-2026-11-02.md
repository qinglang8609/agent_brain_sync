# 2026-11-02 · 记忆盒子落地 + 全项目导入

一天从「探讨记忆机制」做成了可运行的系统：七层分层、SQLite 图数据库、亮度检索、
跨项目共享、会话总结托底、知识自我进化。14 个要点见下。

## 一、代码结构

`store.js` 从 1114 行压到 43 行（纯转发壳），职责拆进 9 个子模块。
关键判断：`todo` 的命令入口回到 `todo/task-cmd.js`；闸门注册从 `init.js` 分出
`gate.js`——它和「建骨架」不是一件事，混在一起时那个靠 import 副作用生效的机制看不清。

## 二、七层分层

L1 铁律不立页（就在 `## Rules`），L6 断点不立页（是双链词）。其余五层各有目录。
层归属：frontmatter 的 `layer` 优先 → 按目录推 → 落到 L4；非法值报错不静默。

存量迁移按判据逐页看：**讲某个具体工具怎么用/有什么坑 → L3；讲通用设计规律 → L4**。
实测 12 页转 L3，5 页通用规律留 L4。只靠 tags 关键词猜会把「资源默认值让 OS 分配」
这种通用规律误判成工具经验。

## 三、SQLite 图数据库

`node:sqlite` 内置够用，不引 Neo4j。实测 2 万节点/20 万边：3 跳扩散 0.5ms、
FTS 0.01ms。14 个项目 586 页导入后 rebuild 0.28 秒。

**方向定死：markdown 是真相，库是查询索引。** 曾讨论反过来（库为真相），
评估后否决——那会废掉人工直编 md 的能力与「人工内容一律不覆盖」这条铁律，
单机场景只加复杂度不加能力。

## 四、检索：四个逐层踩出来的坑

见 [[search-relevance-pitfalls]]。最严重的是归一化分母取反，输出过 165 万宽的亮度条。

最后定下的口径：**亮度保持 0.3~1.0 可读区间（不乘层权重），层的作用由排序承担。**

## 五、跨项目

- 查询共享：`search` 扫全库，别的项目标 `[跨项目]`
- 铁律不外借：`rulesOf(project)` 只返回本项目 + 全局的
- 双链语法：`@项目名/页面` 显式跨项目，找不到就悬挂，不退回兜底

实测坑：`findGlobal` 兜底把 `[[index]]`/`[[todo]]`/`[[log]]` 连到别的项目去，
每个项目都有这几个平铺文件，误连 5 条。判据：兜底只在知识页之间发生。

## 六、会话总结

`abs summon` + md5 账本。四条判据：有快照跳过 / md5 一致跳过 / md5 变了要补充 /
活跃会话跳过。`abs log` 与 `abs capture` 落盘时都扫一遍。

加了 size+mtime 预筛（快 74 倍）与账本 day 预判，避免每次全读 55MB。

## 七、知识自我进化

`abs db evolve` 四条信号：推翻 / 断链 / 堆积 / 僵化。前提是把 `superseded_by` 存进库——
原来只在 markdown 一行里，库说不出「被什么取代」。

## 八、导入全部旧项目

16 个 `.brain` 导入 14 个。排除两个：本项目的 `.delta` 隔离副本、corp_agent 的空图谱。

两个真缺陷：
1. 项目名重名（`~/.agents` 与 `~/Documents/软件/.agents`）导致整个 rebuild 撞 UNIQUE 失败
2. 会话流水页压过知识页（流水正文长，bm25 天然占优）

## 九、92 场会话总结

逐项目读用户原话。**42 场是「nihao」「package」这类空输入**，50 场有真实工作。
通读后真正有跨项目复用价值的只有 3 条（小程序审核、MCP 配置迁移、数据库主从）。

其余是具体项目业务操作，留在各自图谱。**能沉淀成规律的很少，因为大部分会话是「干具体活」。**

## 十、安装

默认只装 pi，其余宿主 opt-in。起因：装到不用的宿主上会往那边配置塞 hook/MCP 条目。

**关键发现**：hook 一直指向全局 npm 包，而那是 1.20.1（没 `src/brain/`）——
这些天做的东西在 pi 里全没生效。现已装本地 1.21.0。

## 十一、精简

`agent_brain_sync` 的概念页从 63 页开始，今天新增 12 页。
lint 从 13 条清到 0，做法是先写新页再删旧 source（上次删太快丢过内容）。
