# 来源：omp(oh-my-pi 18.11.1) 宿主接入 API 核实（源码 ~/.bun/install/global/node_modules/@oh-my-p…

TITLE: omp(oh-my-pi 18.11.1) 宿主接入 API 核实（源码 ~/.bun/install/global/node_modules/@oh-my-pi/pi-coding-agent）

与 pi 的差异（决定 abs.pi.ts 不能直接复用）：
1. before_agent_start 事件只有 {prompt, images, systemPrompt: string[]}，
   **没有** systemPromptOptions.promptGuidelines。返回值是 {systemPrompt?: string[]} —— 
   **整体替换**（agent-session.ts:7867 setTurnSystemPromptOverride）。
   pi 是追加式 guidelines，omp 是整体替换 → 必须「基线 + 我们的段」拼接返回。
2. session_start 事件无 reason 字段（pi 有 startup|reload|new|resume|fork）。
3. agent_end 有 willContinue/awaitingAsyncWork —— 非终态 settle 会继续，不能当"这轮真跑完"。
4. tool_execution_end 带 {toolCallId, toolName, result, isError}（pi 的形态不同）。
5. turn_end 带 {turnIndex, message, toolResults}。

相同点（可直接复用逻辑）：session_shutdown / tool_call{input} / ctx.hasUI / ctx.cwd /
ctx.sessionManager.getSessionId() / ctx.ui.setWidget(key, factory, {placement}) /
before_subagent_spawn（omp 新增，pi 无）。

扩展落点：~/.omp/agent/extensions/*.ts（native provider，自动发现 .ts/.js）。
skill 落点：~/.omp/agent/skills/<name>/SKILL.md（native，priority 100，requireDescription: true）。
MCP：~/.omp/agent/mcp.json 的 mcpServers（stdio，command+args）。

来源：omp://extensions.md / omp://hooks.md / omp://skills.md / omp://extension-loading.md
+ 本机源码 types.ts / agent-session.ts 实地核对。
