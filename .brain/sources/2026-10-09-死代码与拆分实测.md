# 现场：死代码检测与 todo.js 拆分（2026-10-09 实测）

配套概念页 [[dead-code-vs-over-export]]。这里是可复制的命令与完整输出。

## 一、死代码检测命令

### 1. 全项目引用扫描（第一步，最粗）

```bash
cd <项目根>
grep -rn "fixMarks\|renameLegacySections\|absHookDir" \
  --include=*.js --include=*.ts --include=*.md . | grep -v node_modules
```

只回显声明行本身 = 全项目零引用。

### 2. 剥声明行后数「文件内真实使用」

Bash 版（注意 `awk` 的正则要转义括号）：

```bash
awk -v n=fixMarks '$0 !~ ("^export function " n "\\(") {print}' src/store.js \
  | grep -c "\bfixMarks\b"
# 输出 0 → 真死代码
```

### 3. 批量：一次判整个文件的所有导出

```bash
node -e '
const fs=require("fs");
const ROOT="/path/to/project";
const srcFiles=fs.readdirSync(ROOT+"/src").filter(f=>f.endsWith(".js"));
const expRe=/^export\s+(?:async\s+)?(?:function|const|let|class)\s+([A-Za-z0-9_$]+)/gm;
// 消费者语料：src + bin + hooks + test + docs
const files=[];
const walk=d=>{for(const e of fs.readdirSync(d,{withFileTypes:true})){
  if(["node_modules",".git",".brain"].includes(e.name))continue;
  const p=d+"/"+e.name;
  if(e.isDirectory())walk(p);else if(/\.(js|ts|mjs|md)$/.test(e.name))files.push(p);
}};walk(ROOT);
for(const f of srcFiles){
  const self=ROOT+"/src/"+f;
  const txt=fs.readFileSync(self,"utf8");
  const names=[...txt.matchAll(expRe)].map(m=>m[1]);
  for(const n of names){
    let hits=0;
    for(const c of files){ if(c===self)continue;
      const t=fs.readFileSync(c,"utf8");
      const m=t.match(new RegExp("\\b"+n+"\\b","g"));
      if(m)hits+=m.length;
    }
    if(hits===0)console.log(f+" → "+n);
  }
}
'
```

### 4. 区分「真死」与「内部在用」

上面在**整个项目**范围数；若想区分「内部在用只是多导出」，
要在**本文件内**剥掉声明行后数：

```bash
node -e '
const fs=require("fs");
const txt=fs.readFileSync("src/store.js","utf8");
const lines=txt.split("\n");
const declIdx=lines.findIndex(l=>/^(export\s+)?(async\s+)?function\s+fixMarks\b/.test(l));
const rest=lines.filter((_,i)=>i!==declIdx).join("\n");
console.log("文件内真实使用:", (rest.match(/\bfixMarks\b/g)||[]).length);
'
# 0 = 真死；>0 = 内部在用（多导出，一般别动）
```

## 二、导出清单比对（拆分等价性证明）

```bash
# 拆分前：记录
node -e '
const t=require("fs").readFileSync("src/todo.js","utf8");
const names=[...t.matchAll(/^export\s+(?:async\s+)?(?:function|const|let|class)\s+([A-Za-z0-9_$]+)/gm)].map(m=>m[1]);
require("fs").writeFileSync("/tmp/exports-before.json",JSON.stringify(names,null,2));
console.log("拆分前导出",names.length,"个");
'
cp src/todo.js /tmp/todo.js.bak     # 留个回滚点

# … 执行拆分 …

# 拆分后：比对
node -e '
const before=require("/tmp/exports-before.json");
import("./src/todo.js").then(m=>{
  const after=Object.keys(m).filter(k=>k!=="default");
  console.log("丢失:",before.filter(n=>!after.includes(n)));
  console.log("新增:",after.filter(n=>!before.includes(n)));
});
'
```

本次结果：`拆分前 55 / 拆分后 55 / 丢失 [] / 新增 []`。

## 三、依赖边的真假判定（剥注释）

```js
// 剥整行注释 + 行尾注释，避免注释里的名字被当成真依赖
const codeOnly = (src) => src.split('\n')
  .filter((l) => !/^\s*(\/\/|\*|\/\*)/.test(l))   // 整行注释
  .map((l) => l.replace(/\s*\/\/.*$/, ''))         // 行尾注释 ← 漏这个就出错
  .join('\n');
```

**实测踩的假边**：`ENTRY_SHAPES` 区间末尾那句

```js
  ], // 任务行/断点行另由 assertTodoContent 卡长度与报告体
```

让第一版分析凭空造出 `spec → validate` 的环。剥行尾注释后该边消失。

## 四、环检测

```js
const edges = { a:['b'], b:['c'], c:['a'] };   // 模块级依赖边
const dfs = (n, path, seen) => {
  if (path.includes(n)) { console.log('环:', path.concat(n).join(' -> ')); return true; }
  if (seen.has(n)) return false;
  seen.add(n);
  for (const m of (edges[n] || [])) if (dfs(m, path.concat(n), seen)) return true;
  return false;
};
for (const k of Object.keys(edges)) dfs(k, [], new Set());
```

## 六、踩过的两个检测脚本坑

### 坑 1：自写正则 vs grep 结果冲突

自写 node 检测脚本因 shell 里 `$` 转义层层塌陷，
误报「10 个导出无人使用」：

```
common.trimBlank / common.sigOfLine / common.REPORT_MARKERS / …
```

但 `grep -l` 当场证明它们**都被跨模块 import 了**：

```bash
grep -rn "from './common.js'" src/todo/*.js
# archive.js: import { today, SEC, isTaskLine, isChildLine, daysAgo } from './common.js';
# structure.js: import { trimBlank, sigOfLine, isPlaceholder } from './common.js';
# validate.js: import { sigOfLine, REPORT_MARKERS, sentenceCount, isTaskLine } from './common.js';
```

**结论：冲突时信 grep。**

### 坑 2：私有名跨模块后必须补 export

原文件里私有的顶层名，拆分后若被别的模块引用，**必须补 `export`**：

```
indexLinkSectionNeeds / trimBlank / isLeafEntry / sigOfLine / REPORT_MARKERS /
sentenceCount / stripStrayBlanks / normalizeTodoIf / isTaskLine / isChildLine /
parseDoneUnits / renderDoneGroups / ARCHIVE_HEADING / splitDoneBody /
mergeArchiveLines / daysAgo / isUndoneLine / isPlaceholder / insertTask
```

共 18 个。这是拆分的必要改动，**不是**「多导出」。

## 七、ESLint 落地（同批做）

从 75 个问题清到 0：

| 类别 | 处理 |
|---|---|
| 未使用变量/import（真死） | 删 |
| 未使用的 API 兼容参数（`log`/`yes`/`maxWaitMs`） | 确认无调用方传后删；或 `_` 前缀 |
| store.js 的「先 import 再 export」 | 配置 `varsIgnorePattern` 显式豁免（有注释说明踩过的坑） |
| 零宽字符 / 稀疏数组 / unicode 字符类 | 项目刻意做法 → 规则显式关闭并写明理由 |
| 转义多余的测试正则 | 等价改写（`[^\[]` → `[^[]`，`\（` → `（`） |

**Prettier 未引入**：实测会重排 40 个文件（几乎全仓），diff 大到无法 review，
用户决定去掉。项目原本无格式化工具，保持现状。
