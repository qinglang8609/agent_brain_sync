# 共享看板：文件格式

> 状态：定稿（2026-11-18）。落到 `code/multi-agent/board.js`。

共享看板是角色之间「互相知道在干嘛」的**唯一渠道**。角色的 `memory` 是私有记忆，看不见别人说了什么；
接力时需要知道当前总任务、谁在场、各自说过什么 —— 这些都从看板读。

## 位置

```
<项目根>/.pi/agents-chat/board.md
```

跟项目走，能提交进 git（换个会话、换个人接手，接得上）。不进全局目录 —— 不同项目的讨论互不相干。

## 格式

```markdown
# 总任务：做登录功能

## 分任务
- [进行中] 方案设计 —— 架构师
- [待办] 后端实现 —— 程序员
- [待办] 安全验证 —— 测试

## 在场成员：架构师、程序员、测试

## 最新动态
- 架构师：建议 OAuth2 + JWT。风险：token 过期后刷新策略没定，得有人接这个。
- 程序员：OAuth2 可行，要引两个依赖（jose、bcrypt），后者是原生模块，部署要注意。
- 测试：得补 OAuth 的异常路径。另外 token 存哪要定，localStorage 有 XSS 风险。
```

四个段，缺一不可，顺序固定：

| 段 | 写法 | 说明 |
| --- | --- | --- |
| 总任务 | `# 总任务：<一句话>` | 整个讨论的题目。改题目 = 开新话题，旧动态不清空但要重新召集 |
| 分任务 | `- [状态] <标题> —— <角色>` | 状态只有四个词：`待办` `进行中` `已完成` `搁置`。一个分任务只归一个角色 |
| 在场成员 | `## 在场成员：A、B、C` | **只有被 `@` 过的人能进这个名单**（见 `relay-rules.md` 的门禁） |
| 最新动态 | `- <角色>：<意见>` | 一条一轮，按时间正序（新的在下）。角色自己不改写别人的行 |

## 读写纪律

**只有主持人写看板，角色只读。** 这条是硬规则，不为了省事放松：

- 角色写看板 → 多个子代理同时改一个文件 → 覆盖对方的内容，而且这种丢数据不会有任何报错
- 主持人写 → 天然串行（接力本来就是一轮一个），也不需要锁

所以角色产出的是**文字**，由主持人决定怎么记进看板（原样记、还是压缩后再记，见下）。

## 写什么、不写什么

**记**：
- 有实质内容的意见（结论、方案、风险、反对理由）
- 角色提出的具体问题（留给下一位接）
- 分任务的状态变化

**不记**：
- 寒暄、附和（「同意」「好」）—— 它会被当成一轮，白烧额度
- 角色重复自己上一轮说过的话（收敛判据要靠这个判断，记进去反而看不出重复）
- 工具调用细节（改了什么文件、跑了什么命令）—— 那是执行阶段的事，见 `relay-rules.md` 的「聊天与干活分离」

## 长度

看板是**每轮都要塞进角色上下文**的东西，会随讨论线性增长。所以：

- 单条动态压到一句话（`board.addTurn()` 超过 `MAX_TURN_CHARS` 就截断并标注）
- 动态条数超过 `MAX_TURNS`（默认 12）时，**旧的压成一行摘要**（由主持人做，不是自动截断）
- 分任务只保留未完成的 + 最近 3 条已完成的

这三条不是优化，是防止上下文随讨论无界膨胀 —— 一个聊了 20 轮的看板塞进每个角色的 prompt，
等于每轮都在为早期内容付费。

## 会话之间

看板是**项目级**的，不是会话级的：

- 关掉 pi 再打开，看板还在（这就是「角色记得上次聊到哪」的依托）
- 想开新话题：把总任务改掉，分任务清空，动态保留（留个上下文）或手动清
- 想归档：把 `board.md` 挪进 `.pi/agents-chat/archive/<日期>-<题目>.md`（约定，未实现自动化）

## 与 abs 的 `.brain/todo.md` 什么关系

没有关系，别混。两者都在项目里，但职责不同：

| | `.brain/todo.md` | `.pi/agents-chat/board.md` |
| --- | --- | --- |
| 给谁看 | 你和 LLM（人的任务看板） | 角色们（讨论白板） |
| 生命周期 | 长期，跨会话累积 | 一个话题一个，聊完归档 |
| 谁写 | 你 / LLM 调 abs 工具 | 只有主持人 |

分任务里「已完成」的条目，要不要落进 `.brain/todo.md` 由你决定 —— 需要的时候让主持人调 `abs todo` 写过去即可，不要两边自动同步。
