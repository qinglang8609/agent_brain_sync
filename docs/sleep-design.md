# abs sleep — 离线整理设计

status: draft（仅方案，未实现）
created: 2026-11-08
关联: [[memory-box-seven-layers]] · [[knowledge-self-evolution]] · 七层亮度是搜索权重，本方案是真的动文件

## 一句话

常驻一个**机械进程**，夜里（或空闲时）对旧会话页做三件事：补空、压缩、提炼。
琐碎的随时间 1000 字 → 500 → 100 → 墓碑；反复出现的提炼成长期记忆（concepts）。
LLM 只在补空和提炼时用便宜小模型，增量喂，不时刻刻跑。

## 不做什么（先划界）

- 不往干活会话的对话里插话（之前 agent_end 注入实报中断，已删，别接回去）
- 不改写 concepts 正文——知识页只能新增，或走已有 supersede
- 不碰 L1 铁律、用户原话段、【落地/否决/仅方案】结论、`(完成 …)` 行
- 不碰 24 小时内还在动的会话
- 不跨项目整理（各 `.brain/` 各管各的）
- 默认 dry-run，不 `--apply` 一个字不动

## 与现有机制的关系（不重造）

| 已有 | sleep 怎么用 |
|---|---|
| 七层 + 亮度衰减 | 只管搜索排序；sleep 才真的压文件。两者不互替 |
| ingest 机械生成会话页 | 骨架是它写的；空骨架由 sleep 补，补不上保持 draft |
| draft 页已被检索过滤 | 「空 = 没填」也要算 draft，别让空页冒充有货 |
| summon 的 md5 账本 | 判重复用：总结过的 jsonl 不再喂模型 |
| supersede | 知识被新认知取代走这条，sleep 不偷偷改 |
| evolve 体检 | 只报不改；sleep 是它的执行者（改不改仍是内容决策，apply 要人点过头一次） |
| editFile 锁 | sleep 改文件走同一把锁，不另起炉灶 |
| git | 每次 apply 前要求干净树，apply 后自动 commit；压错 `git revert` |

## 触发与节奏

- 手动：`abs sleep`（默认 dry-run，打印要动哪些页）
- 定时：launchd / cron 每晚一次（建议 03:00，一晚最多跑一次全量）
- 空闲门槛：本机没有活跃 pi 会话（活跃 = jsonl mtime < 10 分钟）才跑 LLM 段
- 机械段（建索引、判哪些页超龄）不挑时间，跟 `abs db rebuild` 一条路

## 三个动作

### 动作 0（先决）：空页不算数

**判据**：会话页「出了什么问题 / 怎么解决的 / 验证什么命令」三段全空 = 空页。
**动作**：取对应 jsonl 的**尾部**（用户最后几句 + 改过的文件 + 最终结论），喂小模型填三段。
**填不出**（jsonl 太碎/纯闲聊）：保持 draft，检索不收。
**闸门**：ingest 侧同步——生成页时三段全空就直接标 draft，不让空页冒充有货。

### 动作 1：压缩会话页（L5，按年龄阶梯）

| 页龄 | 压到 | 保留 | 砍掉 |
|---|---|---|---|
| < 7 天 | 不动 | — | — |
| 7–30 天 | 原样的过程部分 | 用户原话段、结论【】、验证命令、改过的文件 | 工具调用流水、重复段 |
| 30–90 天 | ≤ 500 字 | 原话摘 3 句最关键的 + 结论 + 命令 | 其余过程 |
| 90–180 天 | ≤ 100 字一行式 | 日期 + 干了什么 + 结论 + 双链到概念 | 原话细节 |
| > 180 天 且已提炼 且当月未被搜到 | 墓碑 | 见下 | 正文 |

**墓碑格式**（可逆，git 里有全文）：

```markdown
---
tags: [session-tombstone]
updated: <压缩日>
status: active
---
# <原日期> 会话（已整理）

- 干了什么：<一句>
- 结论：<【落地/否决/仅方案】+ 一句>
- 全文：git log --follow sessions/<原文件名>
- 归档到：[[相关概念页]]
```

**数字是建议值，实施前用户拍板**；先按这组跑 dry-run 一周，看它想压什么再调。

### 动作 2：提炼（L5 → L3/L4，长期记忆）

**判据**（满足其一）：
- 同一主题词/双链出现在 ≥ 3 场不同会话页
- `sources/` 里同 tag 的待提炼 ≥ 3 条

**动作**：
1. 建（或补）concept 页，走已有四段骨架（触发场景/表现/解法/验证）
2. 判层照旧：具体工具的坑 → L3；通用规律 → L4（判据见 memory-box-seven-layers，不许一律塞 sources）
3. 原会话页 / sources 条目挂 `distilled-into: [[概念页]]` 双链，不删
4. 同主题已有 concept → 只补那段新证据，不重写旧正文；要推翻走 supersede

**人审**：第一版提炼**只提报不动手**（`abs sleep --plan` 列出「这 3 页在讲同一件事，建议合并成 X」），你点头才建页。跑熟了再放开自动。

### 动作 3：遗忘（墓碑）

三条件**同时**满足才压成墓碑：
1. 页龄 > 180 天
2. 已提炼（有 distilled-into）或内容全是工具流水无结论
3. 近 90 天检索没命中过（db 里记 last-hit，没有就当没命中）

**永不**进墓碑：L1/L2、带【落地】且属发版/架构决定的页、用户标 star 的、双链入度高的枢纽页。

## 模型与 token

| 段 | 模型 | 输入 | 量级 |
|---|---|---|---|
| 补空 | 便宜小模型（flash 级） | jsonl 尾部 20–50KB，不整场重读 | 每页 2k–8k tok |
| 压缩 | 同上 | 该页 markdown 本体 | 每页 1k–3k tok |
| 提炼 | 同上 | 3–5 页的结论段拼起来 | 每次 3k–10k tok |
| 机械（判龄/判重/建墓碑骨架） | 无 LLM | — | 0 |

一晚按 10 页算 ≈ 2–5 万 token，一个月一杯咖啡。
**预算闸**：单晚 LLM 花超 10 万 token 强制停，第二天接着（账本记到哪了）。
**判重**：summon md5 账本，同一 jsonl 不二次喂。

## 命令形态

```bash
abs sleep                # dry-run：列出将补/压/提炼/墓碑的页，不动文件
abs sleep --apply        # 真动（首次 apply 前要求看过 dry-run）
abs sleep --only 压缩|提炼|补空
abs sleep status         # 各龄段页数、draft 数、上次跑到哪
```

apply 流程：检查 git 干净 → 改文件 → `abs db rebuild` → 自动 commit（信息写 `sleep: 压缩 N 页 / 提炼 M 页`）。

## 数据流

```
sessions/*.md + 对应 jsonl
      ↓ 机械：判龄 / 判空 / 判重 / 判检索命中
      ↓ LLM（仅补空与提炼，增量）
改 sessions/*.md（压缩/墓碑）· 新增/补 concepts/*.md
      ↓
abs db rebuild → 检索生效
```

## 分期落地

| 期 | 内容 | 验收 |
|---|---|---|
| M1 | 空页闸门（ingest + 检索）+ `abs sleep` dry-run 只列不压 | 3 张历史空页被点名；dry-run 不改文件 |
| M2 | 压缩阶梯 + 墓碑 + git 自动 commit | 对 11-01/11-04 旧页 apply，`abs show index` 行还在，正文变短，revert 可回 |
| M3 | 提炼提报（--plan 人审） | 同主题 3 页被点名建议合并，人不点头不建页 |
| M4 | launchd 定时 + token 预算闸 + last-hit 记录 | 连跑 7 晚，load 输出字节数不涨（读取侧纪律） |

## 验收判据（做完怎么确认）

```bash
abs sleep                  # dry-run 有输出、git status 干净
abs sleep --apply          # 只动列出的页；原话段还在；concepts 只增不改
abs lint                   # 0 problem
abs search <旧会话独有词>   # 墓碑页不冒充全文，能跳到概念页
git log --oneline -3       # sleep 的 commit 可 revert
node --test test/*.test.js # 全绿，新增 sleep 判据测试
```
